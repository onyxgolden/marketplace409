# Maintenance Manager Agent — Phase 2 slice 1 prototype

Synthetic maintenance-health audit over a fixture-only asset/work-order/
PM-occurrence register. Not a CMMS or dispatch planner: it never
dispatches, schedules PM work, closes a work order, purchases parts, or
predicts reliability. Pure Node 24 ESM, zero runtime dependencies, zero
network, zero model calls.

Brief: `results/chatgpt/maintenance-manager-agent-phase2-slice1-brief-2026-10-15.md`
in `onyxgolden/forge-ai-drop`. Shared contract:
`commands/muse/ai-lab-phase2-slice1-common-contract-2026-10-12.md`.

## What it does

`run(task, context) -> result`:

- **Backlog**: OPEN/IN_PROGRESS work orders with `created_date <= as_of`,
  by priority and by age bin (`0-7`, `8-30`, `31-90`, `91+` days,
  inclusive at both named boundaries). Age = `as_of_day - created_day`
  (same-day = 0), civil UTC day indices — no DST/business calendar.
- **Overdue**: backlog items with an explicit `due_date < as_of`. Due
  *today* is not overdue. Missing `due_date` is `unknown`, never
  inferred from priority.
- **PM compliance**: denominator = declared PM occurrences with
  `due_date` inside the task's reporting window AND `due_date <= as_of`.
  Numerator = denominator members with a valid linked `COMPLETED` work
  order whose completion falls inside the occurrence's own
  `[window_start, window_end]` and `<= as_of`. Early/late completions,
  cancelled links and unlinked occurrences are tracked separately, never
  counted. **A single invalid relevant occurrence (orphan asset,
  dangling link, or a link to an integrity-invalid work order) poisons
  the WHOLE compliance measure to `UNVERIFIABLE`** — it is never
  silently dropped and scored as a rate over a smaller denominator.
  Zero due occurrences is a typed `NO_DUE_OCCURRENCES` (verified, if the
  asset population is complete) rather than a 0% or a crash.
- **Integrity findings**: future-created work orders, orphan asset
  references, invalid/missing/future completion dates, dangling or
  invalid PM links — each excluded from its own measure, cited, and
  listed, without poisoning unrelated clean records.
- Duplicate `work_order_id` / `occurrence_id` / asset id **refuses the
  whole task** — never silently deduplicated.

## Budget discipline

Two lessons carried forward from earlier slices in this program:

1. **Per-candidate charging** (Financial Manager / Executive Manager
   precedent): every work order and every PM occurrence is charged via
   `budget.countObject()` as the first statement of its loop iteration,
   before any of its own fields are read.
2. **Trusted-context charging** (Customer Success / Document Agent
   precedent): the context's own registry — principal, criteria, read
   grants, source keys, revisions — is charged under the exact same
   monotonic budget, via `src/contextGuard.js`, before any domain
   candidate is touched. Registered revision bytes are charged against
   the payload budget the instant their shape is validated, regardless
   of whether that revision is ever actually resolved for use.

The approved corpus root is supplied externally (`MM_APPROVED_ROOT`
environment variable, never written by this package's own scripts) —
see `corpus/freeze-corpus.js`.

## Commands

- `MM_APPROVED_ROOT=<digest> npm test` — authenticated unit tests
- `MM_APPROVED_ROOT=<digest> npm run battery` — authenticated frozen
  battery (120 cases)
- `node corpus/freeze-corpus.js` — recompute the corpus digest after any
  corpus-affecting change (authoring tool, not part of the scored path)
- `node fixtures/make-fixtures.js` then `node corpus/make-battery.js` —
  regenerate fixtures/battery from the authoring scripts (authoring
  tools)
- `node runner/run-manual.js <set-name>` — run one named fixture set
  manually and print the canonical JSON result

## Layout

- `src/` — the agent: `index.js` (entry), `schemas.js` (validation),
  `resolver.js` (budget + Git-object resolution + span verification),
  `contextGuard.js` (charged context walk), `audit.js` (backlog/aging/
  PM-compliance/integrity computation), `injection.js` (seeded-directive
  recognizer), `canonical.js` (canonical JSON, Git blob hashing, exact
  rational arithmetic).
- `fixtures/` — `make-fixtures.js` (authoring tool) + `store.json`
  (generated fixture Git-object store).
- `corpus/` — `oracle.js` (independent re-derivation of the rules,
  authoring-only), `make-battery.js` (authoring tool) + `battery.json`
  (generated), `manifest.json` + `corpus_digest.txt` (generated by
  `freeze-corpus.js`).
- `tests/` — `run-tests.js` / `run-battery.js` (trust-authenticating
  entrypoints), `harness.js` (battery runner), `watchdog.js` /
  `case-worker.js` (worker-thread timeout isolation), `*.test.js`
  (focused unit tests).
- `runner/run-manual.js` — standalone manual exploration tool.

## Non-goals

No real asset/maintenance/customer/tenant data. No scheduling PM work,
dispatch, purchasing, work closure, or reliability prediction. No
application routes, UI, production schema, scheduler, or live adapters.
No activation, no merge, no production writes, no spend, no model calls.
