# Project Management Standard

Status: Draft

## Purpose

Define how AI-supported engineering projects are initiated, planned, executed, paused, resumed, and closed.

## Required Project Documents

Every active project should maintain:

- project charter,
- current status,
- roadmap,
- active objective,
- milestone register,
- architecture overview,
- risk register,
- decision register,
- incident register,
- validation history,
- continuation instructions.

## Project Lifecycle

1. Concept
2. Charter
3. Architecture
4. Foundation
5. Minimum viable product
6. Validation
7. Controlled expansion
8. Production readiness
9. Operations
10. Retirement or replacement

## Objective Definition

Every objective should state:

- desired outcome,
- reason,
- scope,
- exclusions,
- dependencies,
- authority required,
- validation requirements,
- completion criteria.

## Phase Rules

A phase should:

- have one primary outcome,
- begin with repository inspection,
- avoid unrelated cleanup,
- close with validation evidence,
- record the next safe starting point.

## Pause Procedure

When a project is paused:

- record repository state,
- identify incomplete work,
- record active risks,
- preserve continuation instructions,
- define permitted maintenance,
- identify the condition for resumption.

## Resume Procedure

Before resuming:

- verify the repository baseline,
- review changes made during the pause,
- reload active decisions and incidents,
- validate previous assumptions,
- confirm the current objective remains appropriate.

## Initial Project Decision

FORGE major feature development may be paused while the FORGE Engineering Assistant foundation is built. Critical recovery, maintenance, and documentation work remain permitted.
