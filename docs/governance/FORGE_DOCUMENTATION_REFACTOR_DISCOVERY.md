# Discovery 6

Repository Memory Principle

One of the most important discoveries of the refactor was the distinction between conversation and organizational memory.

Conversation is where ideas are explored.

Repository documentation is where ideas become organizational knowledge.

Repository knowledge becomes the permanent memory of FORGE.

Therefore:

Nothing strategically important should exist only inside a conversation.

---

# Discovery 7

Documentation Principles

The following principles emerged during the refactor.

1. Every important idea should eventually become repository knowledge.

2. Every concept should have exactly one authoritative owner.

3. Every document should clearly state:
   - Status
   - Authority
   - Owner
   - Purpose
   - Dependencies
   - Related Documents

4. Duplicate truth should be eliminated.

5. Historical information should not redefine current authority.

6. Research should precede implementation.

7. Product decisions should precede engineering.

8. Repository knowledge should outlive conversations.

# Discovery 18

Principles Worth Preserving

The following principles emerged repeatedly throughout the documentation refactor.

## Preserve Before Perfect

Capture important ideas before attempting to optimize or reorganize them.

---

## Refactor, Don't Rewrite

When possible:

- preserve existing value;
- improve organization;
- reduce duplication;
- avoid unnecessary replacement.

---

## One Source of Truth

Every important concept should have one canonical owner.

Other documents should reference that owner rather than creating competing definitions.

---

## Evidence Before Opinion

Architectural decisions should be supported by:

- repository evidence;
- research;
- engineering validation;
- documented reasoning.

---

## Documentation Is Engineering

Documentation is not an afterthought.

It is a core engineering discipline that enables:

- continuity;
- maintainability;
- onboarding;
- AI collaboration;
- long-term organizational learning.
